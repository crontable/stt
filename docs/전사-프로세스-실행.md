# 전사 작업을 별도 프로세스에서 실행한다

CLI와 이후 웹 서버는 `@stt/transcription`의 `runTranscription()`을 호출한다. 이 함수는 모델 준비, FFmpeg 변환, Whisper 음성 인식과 결과 저장을 별도 Node 프로세스에 맡긴다. 호출한 프로그램의 작업 폴더와 환경 변수는 유지한다.

## CLI에서 실행한다

기존 명령과 입력·결과 위치를 그대로 사용한다. 상대 입력 경로는 CLI를 실행한 작업 폴더를 기준으로 해석하며, 결과는 저장소 루트의 `output/`에 저장한다.

```bash
pnpm start --input /absolute/path/recording.wav
WHISPER_MODEL=base pnpm start --input /absolute/path/recordings
```

Ctrl+C를 누르면 해당 전사 작업과 자손 프로세스를 종료하고 임시 파일·잠금을 정리한다. CLI의 종료 코드는 `130`이다. `SIGTERM`으로 종료 요청을 받으면 같은 정리 후 `143`으로 종료한다.

입력 선택과 지원 형식은 [명령줄 입력 경로 지정](명령줄-입력-경로-지정.md), 엔진 빌드와 large-v3 준비는 [위스퍼 대형 모델 업그레이드](위스퍼-대형-모델-업그레이드.md)를 따른다.

## 다른 앱에서 호출한다

저장소의 앱 패키지에 `@stt/transcription`을 `workspace:*` 의존성으로 연결한 뒤 다음처럼 호출한다. 브라우저 화면 코드에서 이 패키지를 가져오지 않는다. 파일과 프로세스를 사용할 수 있는 Node 서버에서 실행한다.

```js
const { runTranscription } = require('@stt/transcription');

async function transcribeRecording(controller) {
  const results = await runTranscription({
    assetsDir: '/absolute/path/stt/assets',
    outputDir: '/absolute/path/stt/output',
    inputPath: '/absolute/path/recording.wav',
    modelName: 'large-v3',
    signal: controller.signal,
    onProgress: (event) => console.log(event),
    onLog: ({ stream, text }) => process[stream].write(text),
  });
  return results;
}
```

호출하는 쪽에서 `AbortController`를 만들고 `transcribeRecording(controller)`에 전달한다. 실행 중 취소하려면 그 `controller`에서 `abort()`를 호출한다. 반환된 Promise는 자손 종료와 자원 정리가 끝난 뒤 결과 또는 오류를 전달한다.

| 값 | 역할 | 처리 규칙 |
|---|---|---|
| `assetsDir` | 기본 음성 자료 폴더 | 절대 경로를 지정한다. `inputPath`를 생략하면 이 폴더의 지원 파일을 처리한다. |
| `outputDir` | 텍스트 결과를 저장할 폴더 | 절대 경로를 지정한다. 같은 이름의 기존 결과는 새 결과 저장을 마친 뒤 교체한다. |
| `inputPath` | 선택한 파일 또는 폴더 | 선택값이다. 상대 경로는 호출한 부모의 작업 폴더를 기준으로 해석한다. 입력 오류는 모델 준비 전에 반환한다. |
| `modelName` | 사용할 Whisper 모델 | 기본값은 `large-v3`다. `large`도 검증한 large-v3 파일을 사용한다. |
| `signal` | 작업 취소 신호 | 선택값이다. 시작 전에 취소했으면 프로세스를 만들지 않는다. |
| `onProgress` | 구조화된 진행 이벤트 | 선택값이다. 동기 함수와 비동기 함수를 받을 수 있다. |
| `onLog` | 엔진의 표준 출력·오류 | 선택값이다. `{ stream: 'stdout' 또는 'stderr', text }`를 전달한다. 로그를 전사 결과로 사용하지 않는다. |

결과는 입력별 목록이다. 성공 항목은 `{ success: true, inputFile, outputFile }`, 실패 항목은 `{ success: false, inputFile, error }`다. `inputFile`은 처리한 입력 경로이고 `outputFile`은 `outputDir` 아래의 텍스트 파일 이름이다. 한 파일이 실패해도 같은 배치의 다음 입력을 처리한다. 반환 목록에 실패 항목이 있는지는 호출하는 앱에서 확인한다.

초기화 실패, 취소, 자원 충돌과 실행 프로세스 이상은 Promise 오류로 반환한다. 진행 콜백이나 로그 콜백이 실패해도 작업을 종료·정리한 뒤 오류를 전달한다.

## 모델과 결과 파일을 보호한다

| 자원 | 보호 방법 | 충돌 시 동작 |
|---|---|---|
| 모델 준비 | 실제 모델 파일 옆의 `.stt-lock`으로 준비 작업을 보호한다. `large`와 `large-v3`는 같은 파일을 사용한다. | 준비 중인 같은 모델을 요청하면 `STT_RESOURCE_BUSY` 오류를 반환한다. 준비가 끝나면 잠금을 해제한다. |
| 결과 저장 | 실제 출력 폴더의 `.stt-locks/`에서 결과 이름별 잠금을 둔다. 이름은 한글 유니코드 표현과 대소문자를 정규화한다. | 다른 작업이 같은 결과를 만들고 있으면 `STT_RESOURCE_BUSY` 오류를 반환한다. |
| 임시 파일 | 작업마다 별도 임시 폴더를 만들고 자식의 `TMPDIR`·`TEMP`·`TMP`로 지정한다. 저장 대기 파일에도 작업 식별자를 붙인다. | 정상 완료·오류·취소 후 해당 작업의 파일만 정리한다. 원본 입력과 기존 결과는 보존한다. |

준비된 모델을 사용하고 결과 이름이 서로 다른 작업은 동시에 실행할 수 있다. 웹 요청의 대기·재시도·실행 수는 웹 연결 단계에서 정한다. 이 실행기는 요청을 자동으로 대기열에 넣거나 재시도하지 않는다.

음성 인식 전에 실행 파일을 확인한다. 엔진이 없으면 `STT_ENGINE_UNAVAILABLE` 오류를 반환하며, 전사 실행 중 공용 CMake 빌드를 시작하지 않는다. 모델 파일이 없는 경우 모델 다운로드를 진행하고, 준비 완료 뒤 음성 인식을 시작한다. 음성 인식 실패로 준비된 모델을 삭제하지 않는다.

## 종료와 오류를 확인한다

macOS·리눅스에서는 작업 전용 프로세스 그룹에 종료 신호를 보내며, 종료 요청을 무시하는 자손에는 강제 종료 신호를 보낸다. `ps`로 해당 그룹의 실행 중인 구성원을 확인하며, 이미 종료된 좀비는 실행 중인 자손으로 세지 않는다. 조회 실패나 실행 중인 구성원 잔존은 정리 실패로 반환한다. Windows에서는 해당 작업 PID의 트리를 `taskkill /t /f`로 종료한다.

| 오류 코드 | 의미 | 확인할 내용 |
|---|---|---|
| `STT_ABORTED` | 취소 신호를 받았다. | 같은 작업이 자동으로 재시작되지 않는다. 필요한 경우 앱에서 새 작업을 시작한다. |
| `STT_RESOURCE_BUSY` | 다른 작업이 같은 모델 준비 또는 결과 이름을 사용한다. | 오류의 `resourceKind`와 `resource`로 충돌한 자원을 확인한다. |
| `STT_ENGINE_UNAVAILABLE` | Whisper 실행 파일을 사용할 수 없다. | 오류에 표시된 실제 경로에서 설치 문서의 빌드 절차를 수행한다. |
| `STT_WORKER_EXIT` | 작업 프로세스가 비정상 종료했거나 결과를 보내지 않았다. | `exitCode`·`exitSignal`과 엔진 로그를 확인한다. 결과 파일 존재만으로 성공을 판단하지 않는다. |
| `STT_CALLBACK_FAILED` | 진행 또는 로그 콜백이 실패했다. | 호출한 앱의 콜백 오류를 수정한다. |
| `STT_PROCESS_CLEANUP_FAILED` | 자손 종료를 확인하지 못했다. | 실행 중인 자손의 상태를 먼저 확인한다. 해당 작업의 임시 파일과 잠금은 정리 성공 전까지 보존한다. |

호출한 부모의 기본 `SIGINT`·`SIGTERM` 종료도 활성 작업 정리와 연결한다. 앱이 자체 신호 처리기를 두는 경우에는 그 처리기에서 전달한 `AbortController`를 취소하고 작업 완료를 기다린다. 운영체제의 `SIGKILL`, 전원 종료처럼 정리를 실행할 기회가 없는 종료는 잠금·임시 파일을 남길 수 있다. 남은 잠금을 시간만으로 지우지 않고, 소유 프로세스와 자손이 종료됐는지 확인한 뒤 정리한다.

## 구현 위치와 검사

| 위치 | 책임 |
|---|---|
| `packages/transcription/src/index.js` | 앱이 가져오는 공개 진입점이다. |
| `packages/transcription/src/runner.js` | 입력 검증, 프로세스 실행, 메시지·로그 전달과 작업 정리를 연결한다. |
| `packages/transcription/src/worker.js` | 모델 준비와 전체 전사 호출을 별도 프로세스에서 실행한다. |
| `packages/transcription/src/converter.js` | 기존 원본 보호, 전사 결과 검증과 저장 규칙을 담당한다. |
| `packages/transcription/src/model-preparation.js` | 모델 준비 완료와 실행 엔진 확인을 음성 인식 전에 수행한다. |
| `packages/transcription/src/resources.js` | 모델·결과 잠금과 작업 소유 파일을 관리한다. |
| `packages/transcription/src/process-tree.js`·`parent-lifecycle.js` | 자손 종료와 부모 종료를 작업 수명에 연결한다. |
| `packages/transcription/test/runner.test.js` | 실제 Node 자식·셸·손자 프로세스로 실행·취소·충돌 처리를 확인한다. |

`pnpm lint`는 엄격한 코드 규약을, `pnpm test`는 기존 전사 동작과 실제 프로세스 격리·정리를 확인한다. 모의 엔진 검사와 실제 large-v3 음성 인식 검사는 구분하며, 실제 엔진을 확인할 때는 별도 입력 사본과 출력 폴더를 사용한다.

2026년 10월 3일 macOS에서 엄격한 ESLint와 43개 검사를 통과했다. 실제 large-v3·Metal에서는 12.46초 한국어 합성 음성이 약 6.44초에 텍스트로 저장됐고, 부모 작업 폴더·환경 변수와 입력 해시를 보존했다. 임시 작업 폴더와 모델·결과 잠금의 제거도 확인했다. 합성 음성은 실행 연결을 확인하기 위한 입력이며 일반 녹음의 정확도 평가가 아니다. Linux·Windows의 실제 실행은 이번 기기에서 검증하지 않았다.
