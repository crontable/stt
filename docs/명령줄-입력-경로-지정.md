# CLI에서 입력 경로를 지정해 전사하기

이 문서는 `--input` 또는 `-i` 옵션으로 음성 파일이나 폴더를 선택하는 방법을 설명합니다. 입력을 `assets/`로 옮기지 않고 원래 위치에서 선택할 수 있습니다.

## 1. 실행 위치와 필요한 도구를 확인한다

의존성, FFmpeg, Whisper 실행 엔진은 [저장소의 설치 안내](../README.md)에 따라 준비합니다. CLI 옵션은 Node.js의 기본 옵션 해석 함수를 사용하므로 Node.js 18.3 이상이 필요합니다. 함수의 제공 버전은 [Node.js 공식 안내](https://nodejs.org/download/release/v22.13.1/docs/api/util.html#utilparseargsconfig)에서 확인할 수 있습니다.

기존 설치에서 공유 패키지 구조로 옮겼다면 설치 안내의 실제 엔진 경로로 `whisper-cli --help`가 정상 종료하는지 확인합니다. 실행 권한이 있는 파일도 예전 라이브러리 경로를 참조하면 실행에 실패할 수 있으므로, 연결 오류가 나면 설치 안내의 재설정·정리·빌드 절차를 따릅니다.

pnpm 실행 명령은 저장소의 `package.json`에 정의되어 있으므로 저장소 최상위 폴더에서 실행합니다. 아래 `/실제/stt/경로`와 이후 예시의 음성 경로는 해당 기기의 실제 경로로 바꿉니다.

```bash
cd /실제/stt/경로
node --version
```

| 입력 지정 | 처리 범위 | 경로 기준 |
|---|---|---|
| `--input <파일 경로>` 또는 `-i <파일 경로>` | 지정한 파일 한 개 | 절대 경로는 그대로 사용하고 상대 경로는 실행한 작업 폴더를 기준으로 해석합니다. |
| `--input <폴더 경로>` 또는 `-i <폴더 경로>` | 폴더 바로 안의 지원 파일 | 절대 경로는 그대로 사용하고 상대 경로는 실행한 작업 폴더를 기준으로 해석합니다. |
| 옵션 생략 | 저장소 최상위 `assets/`의 지원 파일 | CLI 진입점의 위치로 계산한 저장소 경로를 사용합니다. 실행한 작업 폴더와 관계없이 같은 기본 입력을 선택합니다. |

## 2. 파일 한 개를 지정한다

공백이 있는 경로는 따옴표로 감쌉니다. 아래 명령은 지정한 파일만 처리하며 `assets/`의 다른 파일은 처리하지 않습니다.

```bash
# 절대 경로로 지정합니다.
pnpm start --input "/실제/녹음 자료/회의.m4a"

# 상대 경로와 짧은 옵션으로 지정합니다.
pnpm convert -i "../녹음 자료/회의.m4a"
```

`pnpm start`와 `pnpm convert`는 모두 `apps/cli/src/index.js`의 CLI를 실행합니다. `node apps/cli/src/index.js --input "/실제/녹음 자료/회의.m4a"`처럼 Node.js로 직접 실행할 때도 같은 옵션을 사용할 수 있습니다.

다른 작업 폴더에서 실행할 때는 CLI 진입점을 절대 경로로 지정합니다. 아래 명령의 `회의.m4a`는 명령을 실행한 작업 폴더 안에서 찾고, 결과는 저장소 최상위의 `output/회의.txt`에 저장합니다.

```bash
node /실제/stt/경로/apps/cli/src/index.js --input "회의.m4a"
```

지원 확장자는 `.mp3`, `.wav`, `.m4a`, `.flac`, `.ogg`, `.mp4`, `.avi`, `.mov`이며 대소문자를 구분하지 않습니다. 예를 들어 `회의.WAV`도 처리할 수 있습니다.

## 3. 폴더의 파일을 일괄 처리한다

```bash
pnpm start --input "../녹음 자료"
```

폴더 바로 안의 지원 파일을 순서대로 처리합니다. 지원하지 않는 확장자의 파일은 제외하며 하위 폴더를 재귀적으로 탐색하지 않습니다. `.wav`처럼 음성 확장자가 붙은 폴더도 입력 파일로 선택하지 않습니다.

지원 파일이 하나도 없으면 안내 메시지를 표시합니다. 모델 준비와 초기화가 성공하면 정상 종료합니다. 이 경우에도 모델 준비와 `assets/`·`output/` 폴더 생성은 진행될 수 있습니다.

## 4. 결과와 원본 보존을 확인한다

결과는 입력 파일의 위치와 명령을 실행한 작업 폴더에 관계없이 저장소 최상위의 `output/파일이름.txt`에 저장합니다. 예를 들어 `/실제/녹음 자료/회의.m4a`의 결과는 `/실제/stt/경로/output/회의.txt`입니다. 아래 확인 명령은 저장소 최상위 폴더에서 실행합니다.

```bash
cat "output/회의.txt"
```

엔진은 임시 사본을 처리하므로 원본을 덮어쓰거나 삭제하지 않습니다. 실제 전사 파일이 생성되고 내용이 비어 있지 않으며 결과 저장까지 완료되어야 성공으로 표시합니다.

기존 `output/회의.txt`가 있으면 변환 성공 시 새 전사로 교체합니다. 음성 인식이나 결과 저장에 실패하면 기존 전사를 보존합니다.

같은 실행에서 선택한 `회의.mp3`와 `회의.wav`처럼 결과 이름이 겹치는 입력은 모두 실패로 표시합니다. 대소문자나 한글의 유니코드 표현만 다른 결과 이름도 충돌로 처리합니다. 충돌하는 입력은 엔진에 전달하지 않으며, 다른 이름의 입력은 계속 처리합니다.

## 5. 오류와 종료 상태를 확인한다

| 상황 | 동작 | 종료 코드 |
|---|---|---|
| 지정한 경로가 없음 | 모델 준비 전에 오류를 표시합니다. | `1` |
| 직접 지정한 파일의 형식이 지원되지 않음 | 모델 준비 전에 오류를 표시합니다. | `1` |
| `--input` 값 누락·빈 값 또는 알 수 없는 옵션 | 모델 준비 전에 오류를 표시합니다. | `1` |
| 지정한 폴더에 지원 파일이 없음 | 파일 없음 안내를 표시합니다. 모델 준비는 진행될 수 있습니다. | 모델 준비와 초기화가 성공하면 `0` |
| 선택한 입력끼리 결과 이름이 겹침 | 모델 준비 후 충돌하는 입력을 실패로 표시하고 나머지는 계속 처리합니다. | `1` |
| 입력 읽기·음성 인식·결과 저장 실패 | 해당 입력을 실패로 표시하고 나머지는 계속 처리합니다. | `1` |
| 선택한 파일의 변환이 모두 성공함 | 성공 개수와 생성된 결과 경로를 표시합니다. | `0` |

파일 경로의 존재 여부와 직접 지정한 파일의 확장자는 모델 준비 전에 확인합니다. 개별 파일의 실제 읽기 가능 여부는 변환 단계에서 확인하며, 모델 준비나 초기화 자체가 실패해도 종료 코드는 `1`입니다.

## 6. 도움말을 확인한다

```bash
pnpm exec node apps/cli/src/index.js --help
# 또는
node apps/cli/src/index.js -h
```

도움말은 모델 준비와 음성 인식을 실행하지 않습니다. pnpm 12에서 `pnpm start --help`는 pnpm 자체의 도움말을 표시하므로 위 명령으로 프로그램의 도움말을 확인합니다.
